# 动物森友会式语音：中文与多语言实现整理

> 范围说明：本文后半部分讨论的是“如何复刻类似效果”的通用工程方案，不等于 ACNH 本体实现。关于 Nintendo Switch《集合啦！动物森友会》（ACNH）的资源证据、可以确认的结论和仍未公开的部分，请以同目录的 `acnh-speech-research.md` 为准；GameCube 旧作不再作为 ACNH 的实现证据。

## 结论先行

这类声音不是传统意义上的“把整句话自然地读出来”，而是把屏幕文本拆成很短的、与语言有关的发音单元，再快速串接，并叠加角色化的音高、速度和节奏变化：

```text
文本 → 规范化 → 语言专属发音分析 → 短采样查表 → 串接/停顿 → 变调与变速 → 播放
```

中文最实用的拆法是“汉字 → 拼音 → 声母/韵母”；日文适合按假名或拍；韩文适合把 Hangul 拆成初声/中声/终声；英语等拼音文字可以按字母做近似，也可以先做 grapheme-to-phoneme（G2P）再按音素播放。真正决定“像不像动森”的，除了拆分方式，还有极短采样、较快播放、角色音高和轻微的逐单元音高摆动。

需要区分两件事：公开资料能观察和复现 Animalese 的行为，但 Nintendo 没有公开 ACNH 语音系统的完整工程实现。`ChineseGibberish` 和给定教程是中文复刻方案的直接证据，却不是 ACNH 源码或原作算法证据。

## 两份素材给出的核心观察

短视频把复刻流程归纳成五步：录一遍中文声母/韵母；切成短片段；用随机或文本映射触发并用触发速度控制语速；整体升高约一个八度或更多；再用音高量化/包络制造抑扬顿挫。画面可以确认第五步使用的是 **Waves Tune Real-Time**。若要说固定台词，就手工或程序化地按文本排列发音，而不是继续完全随机。

长音频提出了一个很有用的设计目标：**语义信息接近零，但语言身份和情绪感知很强**。它进一步讨论了几种角色维度：基础音高、语速、随机音高、滤波/明暗、共振峰、同一发音的多个变体，以及句首句尾和口头禅的拉长。节目也把这套方案放进游戏史里理解：早期存储限制促成“小采样库 + 大量组合”，后来即使容量不再紧张，它仍因本地化、角色塑造和沉浸感而成为一种主动的艺术选择。

长音频中的具体 Nintendo 实现细节明确被讲者称为“有根据的猜测”，不能当成源码级事实；但它对复刻目标、听觉机制和产品价值的分析，与短视频、本地 Unity 工程及公开开源实现彼此吻合。

## 给定中文工程实际做了什么

`ChineseGibberish` 是一个很小的 Unity 实现，核心只有三个环节。

### 1. 汉字转成无声调拼音，并提前拆成声母/韵母

`PinYinSpell.cs` 使用 GB2312 查表。它的 `_PinYinSplit` 不是输出完整的 `zhuang`、`hao`，而是预先写成类似 `zh u ang`、`h ao` 的单元序列。标点在 `PreProcess` 中统一变成 `_`，其余 ASCII 字符会被丢弃；因此这个版本主要面向中文，不适合直接混读英文和数字。

它不保留声调。这一点很重要：结果保留了中文音节的可辨识骨架，却主动放弃自然普通话所需的词汇声调，因而更接近“听得出原句轮廓的拟声”。

### 2. 查找 47 个声母/韵母采样与 1 个停顿采样

`PronounceCore.cs` 的 `AllSoundClips` 映射 47 个发音采样，以及 `_` 对应的空白采样。随附 WAV 的长度大多约 0.21–0.36 秒，停顿采样约 0.60 秒。README 也明确说明：使用前需要准备这 47 个声母/韵母音频和一个停顿音频，可自行录制，再用 `split_audio_by_silence.py` 按静音切分。

### 3. 顺序播放，并通过 AudioSource 改变角色感

`CoSpeak` 按单元逐个设置 `AudioSource.clip` 并播放；`trimBegin` / `trimEnd` 可裁掉采样头尾。Unity `AudioSource.pitch` 同时影响音高与实际播放时长，所以提高 pitch 会一起造成“更尖、更快”的效果。这个版本没有做交叉淡化、共振峰保持或独立 time-stretch，因此拼接感本身也是风格的一部分。

可把“大家好！”近似理解成：

```text
汉字：大  家  好  ！
拼音：da  jia hao  pause
单元：d a | j a | h ao | _
```

实际拆分以工程里的旧式拼音表为准，上例只用来说明数据流。

## 多数语言下的共同架构

| 语言类型 | 建议的最小单元 | 优点 | 常见问题 |
| --- | --- | --- | --- |
| 中文 | 拼音声母 + 韵母，可选声调 | 采样库小，汉字覆盖广 | 多音字、儿化、轻声、变调；去声调后可懂度下降 |
| 日文 | 假名、拗音组合或“拍” | 文字与音节关系直接，串接自然 | 促音、长音、拨音需单独规则 |
| 韩文 | 初声 + 中声 + 终声 | Hangul 可算法分解 | 连音、音变若忽略会有机械感 |
| 英语等拼音文字 | 字母，或 G2P 后的音素 | 字母法实现最简单；音素法更像讲话 | 字母名不等于单词发音；重音与弱读复杂 |
| 法/德/西/意等 | 语言专属 G2P 音素 | 拼写到发音通常比英语规则 | 仍需处理连音、重音和地域变体 |
| 不支持的语言 | 字符哈希到一小组拟声采样 | 永远有输出，成本最低 | 与原文本发音几乎无关 |

一个开源的 Animalese 风格实现也采用同样的四层分工：语言 analyzer 把文本拆成音素；sampler 从 audio sprite 中取对应片段；effect 控制 pitch、speed、随机音高和旋律摆动；player 负责顺序播放。它为韩文实现初/中/终声分解，为日文做假名映射，为英文提供字母分析，并把空格与标点停顿作为单独参数。[animalese-tts 源码与说明](https://github.com/izure1/animalese-tts)

社区资料将 Animalese 概括为：文本中的字母或字符会映射成当前游戏语言里的基础发音，角色/性格再改变音高；不同作品的具体方法并不完全相同。日文因为假名天然接近音节，通常比逐字母的英文更容易听懂。[Nookipedia: Animalese](https://nookipedia.com/wiki/Animalese)

## 为什么它听起来像语言，却又不是完整 TTS

1. **时间同步很强。** 每出现一个字或少量字符就触发一个短音，耳朵会把视觉文本和声音自动绑定。
2. **保留局部发音线索。** 即使没有完整音节、声调或协同发音，声母、元音或字母音仍足以提示原句。
3. **速度压缩掩盖了拼接瑕疵。** 单元很短、语速很快，听者没有时间逐个审视。
4. **角色参数比“声音演员”更便宜。** 共用一套采样，只改变 base pitch、speed、随机扰动和旋律包络，就能做出大量角色。
5. **标点承担韵律。** 逗号、句号和换行决定停顿，比完整的语法韵律模型简单很多，却能显著改善“在说话”的感觉。
6. **字幕承载信息，声音承载情绪。** 玩家按文字理解语义，同时把音高、节奏和角色音色解释成“正在说这句话”；这也解释了为什么移开字幕后往往听不出具体内容。

它与现代神经 TTS 的差别是：后者从整段文本预测连续声学特征，追求自然、清晰和上下文韵律；Animalese 风格系统刻意保留离散、短促、夸张和略不可懂的特征。

## 如果要做一个更稳的中文版本

建议保留 `ChineseGibberish` 的小样本思路，但升级文本前端和播放引擎：

1. 用现代中文分词和多音字消歧得到带调拼音，而不是 GB2312 单字静态表。
2. 把音节规范化成声母、介音、韵腹/韵尾；采样库可以继续小型化，也可直接按完整声韵组合录制以提高连贯度。
3. 把声调映射为很弱的 pitch contour，而不是完全丢弃；幅度要小，避免真的变成正常普通话 TTS。
4. pitch-shift 与 time-stretch 分离。角色音高不应被迫改变语速；需要时再用独立 speed 参数控制节奏。
5. 每个单元加 5–15 ms 淡入淡出或短交叉淡化，避免点击声；但不要把边界磨得过于自然。
6. 空格、逗号、句号、问号、感叹号使用不同停顿长度，并让问句/感叹句改变末尾旋律。
7. 为每个角色只存参数预设：基础音高、音域、语速、随机度、旋律幅度、停顿倍率；共享同一套音素采样。
8. 中英混排时分别路由到中文拼音前端和英文 G2P 前端，再合并同一播放队列。

推荐的数据结构是 `Token { phoneme, duration, pitch, gain, pauseAfter }`。文本分析只生成 token；采样、效果和播放保持独立。这样以后扩展日文、韩文或英语时，不需要改动音频引擎。
